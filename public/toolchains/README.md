# Browser toolchains

These content-addressed compiler, linker, sysroot, and runtime assets execute locally through
Wasmer. They are distributed by the five `@wasm-oj/toolchain-*` packages. Browser and server hosts
must receive the packages' explicit `browserSource(baseUrl)` or `serverSource()` values; there is no
default asset base, bundled toolchain, CDN lookup, or filesystem search. A browser `baseUrl`
identifies the HTTP directory containing the declared asset basenames. WASM-OJ appends the pinned
lowercase SHA-256 as a `sha256` query parameter, verifies byte length and digest before use, and
rejects ambiguous asset ownership. The bundled service worker intercepts only same-origin GET
requests carrying exactly one valid `sha256` query and caches a response only after verifying its
bytes; a cross-origin asset host controls its own caching. Source code is never part of an asset
request.

The independent source packages are `@wasm-oj/toolchain-clang`,
`@wasm-oj/toolchain-rust`, `@wasm-oj/toolchain-go`, `@wasm-oj/toolchain-python`, and
`@wasm-oj/toolchain-javascript`.

The `.gz.bin` suffix is intentional. It prevents static hosts from treating the stored gzip artifact as HTTP `Content-Encoding: gzip`; the Worker receives the compressed bytes and performs exactly one explicit decompression before Wasmer instantiation.

The small TypeScript and QuickJS adapters provide deterministic stdin/stdout protocols so the toolchain does not depend on host filesystem access. Rebuild or refresh assets with:

```sh
pnpm run toolchain:browser:prepare /absolute/path/to/wasi-sdk-24.0-arm64-macos.tar.gz
pnpm run toolchain:rust:prepare /absolute/path/to/rust.tar.br
pnpm run toolchain:go:prepare
pnpm run toolchain:python:prepare /absolute/path/to/Python-3.14.6.tar.xz /absolute/path/to/Python-3.14.6.tar.xz.spdx.json /absolute/path/to/wasi-sdk-24.0-arm64-macos.tar.gz
pnpm run toolchain:clang:prepare
```

The C/C++ `wasip1` and `wasix` WASM-OJ profiles both consume this one WASI P1 manifest. `wasix` changes artifact, cache, cost-calibration, and runtime-profile identity; it does not select another Clang target, linker command, or runtime implementation. The runner validates the module's actual imports.

`pnpm run toolchain:browser:prepare /absolute/path/to/wasi-sdk-24.0-arm64-macos.tar.gz`
requires the official arm64 macOS WASI SDK 24.0 release archive. It verifies the
archive SHA-256 `aeae9993…b0b3a`, the exact Clang, LLD, strip tool, crt1,
wasi-libc, emulated-signal, libm, and compiler-rt inputs, then builds QuickJS-ng
at the pinned commit. The script strips debug sections, verifies the expanded
Wasm SHA-256 `f06b8bf3…bc686`, creates deterministic gzip, and publishes both
browser assets atomically.

`pnpm run toolchain:python:prepare …` verifies the official CPython source
archive, its archive-bound SPDX document, and WASI SDK archive before building
the native bootstrap interpreter and `wasm32-wasip1` interpreter from scratch.
It requires `_socket` to be absent, canonicalizes and reads back packaged
sysconfig data, verifies the exact WASI import set and complete license closure,
then executes the package through Wasmer. That smoke reproduces the 10,652,540-
byte `WOJFS002` standard-library archive with SHA-256
`44d894f91487f20c2bb04fe496a9343db37d8720fb706472c2b4a7f3300db039`.

`pnpm run toolchain:clang:prepare` downloads the fixed npm archive, verifies its archive, compiler-core, and resources digests, rebuilds the WebC deterministically, asks the packaged driver for its exact job expansion, freezes the resulting cc1/link argv, and verifies every output digest. Runtime compilation uses only these verified bytes and fails explicitly if an asset or digest does not match.

`pnpm run toolchain:rust:prepare /absolute/path/to/rust.tar.br` verifies the
exact artifact from the pinned upstream Actions run, downloads and verifies the
pinned YoWASP linker archive, and reconstructs one WebC from the rustc and LLVM
atoms plus their matching sysroot/resource volumes. It normalizes filesystem
timestamps, freezes the exact two-stage linker contract, verifies package and
provenance-manifest digests, and atomically replaces both published assets. The
source build repository pins Rust and LLVM submodules and contains the applied
patches and complete source-traceable build workflow used for the rustc artifact.

`pnpm run toolchain:go:prepare` verifies the official Go 1.26.5 distribution for
the current packaging host and records the official source-distribution URL and
SHA-256 as stable provenance. It invokes the standard Go build to obtain the
`wasip1/wasm` compiler, linker, and complete standard library, then packages and
verifies their WebC command ownership and deterministic archive. Repeating the
packaging operation must reproduce the three published digests above.
